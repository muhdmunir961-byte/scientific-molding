# M3 — Fundamental of Scientific Moulding: Process Development

**2 days · Bridge · Build the essential principles behind structured process development.**

## 1. Headline

- [ ] **FUNDAMENTAL OF SCIENTIFIC MOULDING: PROCESS DEVELOPMENT**

## 2. Six problems this module helps solve

- [ ] **Unstructured start-ups** — the process is set up differently each time, depending on who is on shift.
- [ ] **No development phases** — filling, packing and cooling are adjusted together without separating their roles.
- [ ] **Settings recorded, evidence ignored** — values are written down, but actual process outputs are not read.
- [ ] **No shared meaning of "stable"** — teams do not agree on what repeatable means.
- [ ] **Data collected but unused** — numbers are gathered without a clear purpose.
- [ ] **Not ready for advanced learning** — the basics are missing, so advanced development training is hard to absorb.

## 3. Five business benefits

- [ ] **01 · More organised start-up** *(Efficiency)* — replace random adjustment with a clear development sequence.
- [ ] **02 · Clearer process thinking** *(Understanding)* — connect each process phase to what the plastic experiences.
- [ ] **03 · Better use of process data** *(Data)* — turn recorded values into usable evidence.
- [ ] **04 · Shared development language** *(Teamwork)* — align engineering, production and quality.
- [ ] **05 · Readiness for advanced capability** *(Growth path)* — prepare the team for 4-day Process Development.

## 4. Before / After

- [ ] Adjust settings until parts look acceptable → Follow a phase-by-phase development logic
- [ ] Record setpoints only → Read actual outputs alongside setpoints
- [ ] "Stable" means "it ran well today" → Repeatability has a shared meaning and indicators

## 5. Five practical outcomes

- [ ] Describe the process phases and what each is meant to achieve.
- [ ] Separate process inputs from actual process outputs.
- [ ] Read basic process data and explain what it suggests.
- [ ] Explain what repeatability means and recognise its basic indicators.
- [ ] Record process information clearly for the wider team.

## 6. Course structure

**Day 1: Understand the structure**

- [ ] Why development must be structured
- [ ] The four plastic conditions (Temperature | Flow | Pressure | Cooling)
- [ ] Process phases
- [ ] Inputs versus outputs

**Day 2: Apply the basics**

- [ ] Basic data thinking
- [ ] Recording and documenting
- [ ] The concept of repeatability
- [ ] A simple development sequence applied to a prepared case study
- [ ] Readiness review and pathway to M4

## 7. Who should attend + format

- [ ] Process engineers and technicians
- [ ] Setup technicians
- [ ] Production supervisors
- [ ] QA/QC personnel
- [ ] **Recommended after M1 and M2**
- [ ] Learning format: Guided discussions | Process diagrams | Prepared data sets | Case studies | Participant worksheets

## 8. Management takeaway

- [ ] *Structured development starts with understanding the process, not with changing settings.*

# M5 — Systematic Parameter Setting for Injection Molding

**2 days · Bridge · Introduce a consistent framework for parameter-setting decisions.**

## 1. Headline

- [ ] **SYSTEMATIC PARAMETER SETTING FOR INJECTION MOLDING**

## 2. Six problems this module helps solve

- [ ] **Settings differ by person** — the same mould is set up differently on every shift.
- [ ] **Changes without a reason** — parameters are changed with no stated intent.
- [ ] **Several changes at once** — the team cannot tell which action worked.
- [ ] **No agreed order of decisions** — setting discussions jump randomly between parameters.
- [ ] **Copied setups** — values from a similar job are reused without checking the conditions.
- [ ] **Reasoning not recorded** — the next person inherits numbers but not the logic.

## 3. Five business benefits

- [ ] **01 · More consistent setups** *(Consistency)* — one method across shifts and personnel.
- [ ] **02 · Clearer setting discussions** *(Communication)* — production, quality and engineering use the same logic.
- [ ] **03 · Fewer unexplained changes** *(Control)* — every change has an intent and a recorded response.
- [ ] **04 · Better setup records** *(Documentation)* — decisions can be followed and reviewed.
- [ ] **05 · Less dependence on individuals** *(Know-how)* — the method belongs to the team, not one person.

## 4. Before / After

- [ ] Change several parameters and hope → Change one thing at a time with a stated intent
- [ ] Copy the last setup → Decide settings from plastic conditions and evidence
- [ ] Numbers handed over without reasons → Rationale recorded for the next person

## 5. Five practical outcomes

- [ ] Explain the logic of each major parameter group in terms of the four plastic conditions.
- [ ] Follow a structured method for deciding and ordering settings.
- [ ] Justify a parameter decision with evidence and a clear intent.
- [ ] Apply controlled changes and record the process response.
- [ ] Communicate and document setting decisions so others can follow them.

## 6. Course structure

**Day 1: Parameter logic**

- [ ] Settings as inputs, not proof
- [ ] Linking parameters to Temperature, Flow, Pressure and Cooling
- [ ] Parameter groups
- [ ] Why a structured sequence matters

**Day 2: Structured method in practice**

- [ ] A step-by-step decision framework on prepared case studies
- [ ] Change control (one change at a time)
- [ ] Recording the rationale
- [ ] Group review of settings and consistency across shifts

## 7. Who should attend + format

- [ ] Process engineers and technicians
- [ ] Setup technicians
- [ ] Production supervisors
- [ ] Technical managers
- [ ] **Recommended after M3**
- [ ] Learning format: Guided discussions | Prepared case studies | Decision worksheets | Process diagrams | Group review

## 8. Management takeaway

- [ ] *A consistent method turns parameter setting from personal habit into shared engineering capability.*
